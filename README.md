# AR Room — персонажи в вашей комнате

Android-приложение: открыл → камера → выбрал (или загрузил свою) 3D-модель → коснулся пола → персонаж стоит в комнате, анимированный, его можно двигать, крутить, масштабировать и сфотографировать.

Стек: **Kotlin + Jetpack Compose + ARCore + SceneView 2.x (Filament)**.

---

## 1. Как запустить

1. Открыть папку в **Android Studio Ladybug (2024.2)** или новее.
2. Gradle синхронизируется сам и скачает ARCore/Filament.
3. Подключить **реальный Android-телефон** из [списка ARCore-совместимых](https://developers.google.com/ar/devices). На эмуляторе AR не работает.
4. Run.

> Wrapper-файлы (`gradlew`, `gradle-wrapper.jar`) не входят в архив — Android Studio создаст их при первом открытии. Либо выполните `gradle wrapper --gradle-version 8.9`.

Минимальная версия Android — **9.0 (API 28)**, это требование SceneView 2.x.

## 3. Формат моделей

Поддерживается **glTF 2.0**: `.glb` (один файл — предпочтительно) и `.gltf`.  
FBX, OBJ, VRM напрямую **не** читаются — конвертируйте через Blender (экспорт → glTF 2.0) или `gltf-transform`.

При импорте файл проверяется до попытки загрузки: размер до 80 МБ, магия glTF в первых байтах, отсутствие Draco и Meshopt. Если что-то не так, человек видит конкретную причину, а не общее «модель не загрузилась».

Требования к модели, чтобы всё выглядело хорошо:
- Скелетная анимация (Idle / Walk / Dance) внутри файла — приложение подхватит их автоматически.
- До ~100k треугольников и текстуры ≤ 2048px, иначе телефон начнёт греться.
- Ось Y вверх, модель стоит в нуле координат.
- `.glb` со сжатием Draco/Meshopt Filament **не** читает — экспортируйте без него.

Свои модели можно:
- положить в `app/src/main/assets/models/` и добавить в `BuiltInCatalog` как `ModelSource.Asset("models/имя.glb")`;
- или отдавать с вашего CDN через `ModelSource.Remote(url)`.

## 3.1. Как получить APK без Android Studio

В проекте лежат два GitHub Actions workflow — ноутбук с Android SDK не нужен вообще.

1. Создайте репозиторий на GitHub и загрузите туда содержимое архива.
2. Вкладка **Actions** → workflow **Build APK** → **Run workflow**.
3. Перед сборкой прогоняются юнит-тесты — если валидатор моделей сломан, APK не соберётся. Через 5–8 минут в артефактах появится `arroom-debug-apk`. Скачайте, перекиньте на телефон, разрешите установку из неизвестных источников.

Второй workflow, **Release bundle**, собирает подписанный `.aab` для Google Play. Перед запуском добавьте в Settings → Secrets четыре значения: `KEYSTORE_BASE64` (ваш keystore через `base64 -w0 upload.jks`), `KEYSTORE_PASSWORD`, `KEY_ALIAS`, `KEY_PASSWORD`.

## 3.2. Про запись видео

Видео пишется захватом экрана (`MediaProjection`), а не рендером из Filament. Причина: AR-кадр — это склейка видеопотока камеры и 3D-слоя, которая происходит уже на уровне композитора системы. Захват экрана даёт ровно ту картинку, которую видит пользователь, без дублирования всего пайплайна рендера.

Интерфейс приложения на время записи уезжает автоматически, поэтому в кадр попадает только AR-сцена. Вернуть панель можно кнопкой «Показать панель», не прерывая запись. В кадре остаётся системная строка состояния — убрать её из захвата экрана штатными средствами Android нельзя.

Звук берётся с микрофона. Отказ от разрешения не блокирует запись — получится видео без звука.

Сейчас в каталоге четыре модели из репозитория Khronos glTF-Sample-Assets — они грузятся **по сети** и лежат под чужими лицензиями (Fox — CC0, CesiumMan и BrainStem — CC-BY 4.0).

## 5. Известные места, требующие проверки при первой сборке

SceneView активно меняет API между минорными версиями. Если что-то не скомпилируется, скорее всего это:

- `Node.parent` в `ArScreen.findCharacter()` — в некоторых версиях называется `parentNode`.
- `modelNode.animator.getAnimationName(i)` — в части версий `animator` приватный; тогда используйте `ModelNode.animationCount` и подписи «Анимация 1/2/3».
- Сигнатура `rememberOnGestureListener` — параметры лямбды `onSingleTapConfirmed`.

Все три места локальны и правятся за пару минут по подсказкам IDE. Версия, на которую рассчитан код: `io.github.sceneview:arsceneview:2.2.1`.

## 6. Что стоит доделать до релиза

Порядок — по влиянию на удержание пользователя:

1. **Свой контент** — 10–15 качественных анимированных персонажей. Это и есть продукт; всё остальное — обёртка.
2. **Аналитика** — сейчас её нет вовсе. Отчёты о падениях приходят почтой и только от тех, кто нажмёт кнопку; для оценки удержания и воронки этого мало. Firebase Analytics или Amplitude — когда появится, что измерять.
3. **Монетизация** — бесплатные 3–4 персонажа, остальные по подписке (Google Play Billing).
4. **Сохранение расстановки** — чтобы персонажи оставались на местах между запусками (ARCore Cloud Anchors или локальные Persistent Anchors).
6. **Онбординг-подсказка про жесты** — анимированная рука, показывающая перетаскивание и щипок при первом персонаже.

## 7. Публикация в Google Play — чеклист

**Технически:**
- [ ] `applicationId` заменить с `com.arroom.characters` на свой (после первой публикации его нельзя изменить).
- [ ] Создать upload-keystore, подключить Play App Signing.
- [ ] Собрать **AAB**: `./gradlew bundleRelease`.
- [ ] Проверить, что `minifyEnabled` не сломал Filament (правила уже в `proguard-rules.pro`) — обязательно протестировать release-сборку, а не только debug.
- [ ] `versionCode` увеличивать при каждой загрузке.
- [ ] Оставить `<uses-feature android:name="android.hardware.camera.ar" android:required="true" />` — Play сам скроет приложение от несовместимых устройств и вы избежите потока однозвёздочных отзывов.

**В консоли:**
- [ ] Обосновать запись экрана и микрофон: Play отдельно проверяет `FOREGROUND_SERVICE_MEDIA_PROJECTION` и требует, чтобы запись запускалась только по явному действию пользователя (у нас так и есть — кнопка).
- [ ] Заполнить **Data safety**: камера используется локально, кадры не передаются и не хранятся. Это обязательный раздел, за неточность снимают с публикации.
- [ ] Политика конфиденциальности — публичная ссылка обязательна, даже если данных не собираете.
- [ ] Возрастной рейтинг (анкета IARC).
- [ ] Иконка 512×512, feature graphic 1024×500, минимум 2 скриншота телефона.
- [ ] Закрытое тестирование: с 2023 года новым разработчикам-физлицам нужно **12 тестировщиков в течение 14 дней** до открытой публикации. Это самый частый затык — планируйте заранее.
- [ ] Аккаунт разработчика: $25 единоразово.

**Юридически:**
- [ ] Права на все 3D-модели, звуки и шрифты. Если пользователь грузит свою модель — добавьте в EULA пункт об ответственности за загружаемый контент и кнопку жалобы (Play требует модерацию UGC).

## 7.1. Кеш моделей

Удалённые модели скачиваются один раз в `cacheDir/models` и дальше грузятся с диска. Побочные эффекты, о которых стоит знать:

- После первого запуска приложение работает офлайн — важно, потому что AR-съёмка часто идёт там, где связи нет.
- Кеш ограничен 400 МБ, самые старые файлы вытесняются первыми.
- Это `cacheDir`, а не `filesDir` — система вправе очистить папку при нехватке места. Это правильное поведение: модель просто скачается заново.

Прогресс в процентах показывается, только если сервер вернул `Content-Length`. При chunked-ответе крутилка бесконечная — врать процентами хуже, чем честно показать, что длительность неизвестна.

## 7.2. Превью в карусели

Миниатюра снимается кадром живой сцены через секунду после того, как персонаж встал на место: кадрируется квадрат вокруг точки касания, приподнятый на четверть стороны (персонаж стоит над точкой, иначе в кадр попадёт в основном пол), и ужимается до 144 px.

Почему не офскрин-рендер модели: полноценный рендер в текстуру через Filament — отдельный пайплайн с `RenderTarget` и `readPixels`, десятки строк хрупкого кода поверх API, которое меняется от версии к версии. Кадрирование живой сцены использует только то, что уже работает.

Минус честный: в миниатюру попадает кусок комнаты позади персонажа, и до первого размещения превью нет вовсе. Пока его нет, плитка красится в стабильный цвет, выведенный из идентификатора модели — свои модели хотя бы различимы между собой.

## 7.3. Ресурсы и нагрев

Две вещи, которые в AR ломаются не сразу, а через несколько минут работы.

**Нативная память.** Меши и текстуры живут на стороне Filament, сборщик мусора Kotlin про них не знает. `CharacterNode.dispose()` останавливает анимации и возвращает ресурсы движку; вызывается при удалении персонажа и при уходе с экрана. Отдельно там же отменяются корутины: цикл idle-анимации написан как `while (isActive)` и живёт столько, сколько живёт scope экрана — то есть после удаления персонажа он продолжал бы тридцать раз в секунду писать в уничтоженный объект.

**Нагрев.** Камера, нейросетевой трекинг и 3D-рендер работают одновременно — это один из самых тяжёлых сценариев для телефона. При `THERMAL_STATUS_MODERATE` лимит персонажей падает до трёх, при `SEVERE` — до одного, и тени переключаются с PCSS на более дешёвый PCF. Человек видит короткое предупреждение, чтобы падение картинки не выглядело поломкой. До Android 10 такого API нет — там поведение прежнее.

## 8. Локализация

Язык по умолчанию — английский (`res/values/strings.xml`), русский лежит в `res/values-ru/`. Все строки интерфейса вынесены в ресурсы, в коде не осталось ни одного зашитого литерала.

Добавить новый язык: скопировать `values-ru/strings.xml` в `values-<код>/`, перевести и дописать код в два места — `locales_config.xml` и `resourceConfigurations` в `app/build.gradle.kts`. Второе нужно, чтобы Play не показывал приложение как переведённое на язык, которого в сборке нет.

`localeConfig` в манифесте даёт пользователям Android 13+ переключать язык именно этого приложения в системных настройках, не меняя язык всего телефона.

## 9.1. Обязательно заменить перед релизом

Два значения в `app/src/main/res/values/strings.xml` помечены `translatable="false"` — их надо подставить свои:

```xml
<string name="support_email">your-email@example.com</string>
<string name="privacy_policy_url">https://example.com/privacy</string>
```

Первый адрес получает отчёты о падениях, второй открывается из настроек. Если оставить заглушки, кнопки в приложении будут вести в никуда.

## 9.2. Как работают отчёты о падениях

Crashlytics требует проекта в Google Cloud и `google-services.json` — на старте это лишняя зависимость. Вместо него `CrashLogger` перехватывает необработанные исключения, пишет стектрейс вместе с моделью устройства, версией Android и списком ABI в файл, а при следующем запуске предлагает отправить его почтой.

Важная деталь: обработчик обязательно передаёт исключение дальше по цепочке. Без этого процесс зависает вместо честного падения, и система не показывает свой диалог.

Отчёт уходит только по явному нажатию. Ничего не передаётся автоматически, поэтому декларацию Data safety менять не нужно — это остаётся приложением, которое не собирает данные.

## 10. Что осталось нарисовать руками

Иконка и обложка готовы. Скриншоты — нет, и снять их можно только на устройстве. Что снимать, по убыванию важности:

1. Персонаж стоит на полу узнаваемой комнаты — крупно, с мебелью в кадре
2. Тот же кадр с рукой, показывающей масштабирование щипком
3. Несколько персонажей в одной сцене
4. Экран загрузки своей модели
5. Карусель с превью

Минимум для публикации — два скриншота, но карточки с шестью конвертируют заметно лучше. Для AR-приложений ещё сильнее работает короткое видео: снимите экран прямо встроенной записью, она для этого и сделана.

## 11. Дизайн-система

Интерфейс прогнан по чеклисту скилла ui-ux-pro-max (стиль Modern Dark / Cinematic поверх камеры). Что изменилось:

**Токены вместо сырых литералов.** Раньше цвета и радиусы были рассыпаны по файлам как `0xCC12121A` и `RoundedCornerShape(20.dp)`. Теперь единственный источник — `Tokens.kt`: акценты, поверхности, текст, радиусы, ритм отступов (кратно 4dp), длительности анимаций. Поменять тон приложения — одна правка.

**Плотность стекла — осознанное решение.** Панели поверх камеры сделаны на 90% непрозрачными, а не «модно-прозрачными». Над ярким окном или белой стеной полупрозрачный фон уронил бы контраст текста ниже нормы WCAG 4.5:1. Читаемость важнее эффекта.

**Не чистый чёрный.** Фоны — `#0B0B12` и `#14141C`. На OLED чистый `#000000` даёт смазывание движущихся объектов; скилл отмечает это отдельно.

**Единое прижатие.** Все кнопки используют `Modifier.pressable`: отклик за ~130ms, масштаб от центра (не сдвигает соседей), ripple. Цель касания везде ≥48dp даже там, где иконка мельче — правило hitSlop.

**Reduced motion.** Пульсации, вращение прицела и «дыхание» гаснут, если пользователь отключил анимации в спец-возможностях.

**Inter.** Один зашитый шрифт вместо системного, который на каждой прошивке свой. Полная кириллица — оба языка приложения выглядят одинаково хорошо.

## 12. Коллекция и экономика

Поверх AR выросла коллекционная игра. Что работает на телефоне уже сейчас:

- **Поимка**: поставил персонажа в комнату — получил карточку и монеты. Первая поимка щедрее, дубли дают символический бонус.
- **Редкость** у каждого персонажа фиксированная (обычная/редкая/эпическая/легендарная), выводится из id — одинакова у всех игроков.
- **Коллекция**: сетка карточек, силуэты ненайденных с замком, прогресс сбора, избранное.
- **Магазин**: покупка карточки за монеты, продажа дублей.
- **Наборы**: три вида паков со случайным выпадением по весам, с анимацией открытия.
- **Ежедневная награда** со стриком: 50 монет в первый день, растёт до 250, сброс при пропуске.
- **Достижения** за вехи коллекции с разовой наградой.
- **Обмен** между людьми — витрина-заглушка, ждёт сервер.

Весь код в пакете `collection/`. Единая точка — `CollectionRepository`: снаружи это методы `catch/buy/sell/openPack/claimDaily/claimAchievement` и потоки `wallet/owned`. При переезде на сервер меняется только нутро этого класса, экраны не трогаются.

**Экономика на клиенте — временно.** Пока монеты и инвентарь в SharedPreferences, их можно отредактировать. Для одиночной коллекции приемлемо; в момент включения обмена источником правды обязан стать сервер. Как это устроить — в `server/ARCHITECTURE.md`.
